Drop a folder. It's a website.

Dropserve is a local web server for people who want to use one, not administer one. Put a folder in, and it's live on your network a second later — no config file, no virtual host, no restart, no port to memorise.

Three steps. That's the whole product.

Every other stack in this category asks you to edit a config file and restart a service before your folder becomes a website. Dropserve treats the filesystem as the configuration.

STEP 01

Install it once

A per-user install with no admin prompt. It creates a Dropserve/Apps folder and starts itself when you log in — from then on it's simply always there.

STEP 02

Drop a folder in

Static HTML, a PHP app, a Node script, a Python tool. Dropserve works out what it is, runs it if it needs running, and puts it on a URL. No manifest required.

STEP 03

Remember one address

Open your machine's IP from any device on the network. Everything you've ever dropped in is there, indexed and searchable. Scan the QR code to open it on your phone.

Built around never making you guess

The features exist to remove a specific moment of friction. If one of them ever makes you open a config file, it's a bug.

Everything is indexed

Names, descriptions, README text and the filenames inside each app are all searchable from one box. Type three letters, hit Enter, you're there. You never have to remember what you called it.

Starts before you do

Registered as a logon task, not a service — so no admin rights, no console window flashing at startup, and one honest toggle that reads the real state from the operating system rather than a checkbox we saved.

Reachable from anywhere

On the network, it's your IP. Outside it, Dropserve picks up your existing Tailscale login and hands you a private HTTPS address that works from any device, anywhere — with no port forwarding and nothing exposed to the internet.

QR code for every app

Point your phone's camera at a card and the app opens. No typing an IP address into a phone keyboard, ever again.

It runs your apps, not just files

A folder with a package.json start script gets a port, an environment variable and a supervised process with live logs. If it crashes, that one card turns amber — everything else keeps serving.

Small, honest, and yours

A single binary of roughly 20 MB, not a 150 MB bundle of things you'll never use. PHP, MariaDB and PostgreSQL install on demand in one click, and uninstall just as cleanly. MIT licensed, no telemetry, no account.

How it differs

The incumbents are stack installers: they set up Apache, MySQL and PHP and hand you a document root. Dropserve starts from a different question — what does it take to get the thing you just made onto your phone?

Verify your download

sha256sum -c checksums.txt

cosign verify-blob \
  --bundle dropserve.sig \
  dropserve.exe

About the Windows security warning. Dropserve is signed with the project's own certificate, which proves the file hasn't been tampered with — but it isn't a certificate bought from a commercial authority, so SmartScreen will still show "Windows protected your PC" on the direct download. Click More info → Run anyway, or install through scoop, which skips the browser-download prompt. Every release also publishes SHA-256 checksums and a Sigstore signature so you can verify it yourself. We'd rather explain this than pretend it doesn't happen.

Questions

Is this a replacement for XAMPP?

For hosting your own small apps and sites on your own machine, yes — and a considerably friendlier one. If your work is specifically WordPress or Laravel development and you rely on per-project PHP versions, WP-CLI integration or a bundled phpMyAdmin, XAMPP or Laragon still fit that better today.

Does it support PHP and MySQL?

Yes, as optional packs. The base install ships neither, which is why the download is around 20 MB instead of 150. The first time you drop a PHP app in, Dropserve offers to install PHP in one click. MariaDB and PostgreSQL work the same way, and both uninstall cleanly. SQLite needs nothing at all — Dropserve will even browse the database file for you.

Do I need Tailscale?

No. Everything on your own network works without it. Tailscale is what makes an app reachable when you're not at home, and Dropserve simply uses the Tailscale you already have installed and logged in — it doesn't ask for a second account or create a second device. Public sharing through Tailscale Funnel is off by default and can only be turned on one app at a time, with a confirmation.

Who can reach my apps?

By default, anyone on the same Wi-Fi or LAN — that's what makes "open it from your phone" work, and the setup screen says so plainly. Each app can be set to local-only, network, or Tailscale-only, and there's an optional PIN for when you're on a network you don't trust.

Worth saying clearly: dropping a folder in means running its code with your own user account. Dropserve doesn't sandbox apps. Drop in things you wrote or trust.

What if my app breaks when it's served under a sub-path?

It's handled. Dropserve forwards the standard proxy headers, rewrites redirects and cookies, and injects a <base> tag where it's safe to. If an app still expects to own the root of a site, Dropserve notices, gives that app its own dedicated address, and tells you it did — you don't have to know any of this happened.

Does it phone home?

No telemetry, no analytics, no account. The only outbound request is a once-a-day check of the GitHub releases page for a new version, which you can switch off. It never downloads or installs an update by itself.

Can I run it on an old laptop or a mini-PC in a cupboard?

That's a good use for it. The tray icon is optional and the whole thing runs headless — dropserve serve on a Linux box with a systemd user unit is a first-class setup.
